Полных дубликатов среди текущих пяти алгоритмов не найдено. Включены все шесть
с исходными идентификаторами: `exact_normalized`, `token_sort`, `token_set`,
`levenshtein`, `jaro_winkler`, `jaccard`. Вместе с прежними пятью в реестре 11.

### Почему Token Sort оставлен отдельным

`copilot_1` выбирает максимум из обычного `fuzz.ratio` и `token_sort_ratio`.
Метод донора использует только Token Sort и собственную нормализацию размеров,
десятичных чисел и `ё`. Эти алгоритмы способны ранжировать кандидатов по-разному.

Контрольный пример без различий нормализации: запрос `болт гайка`, кандидаты
`a: долт гайка` и `b: болт гайки`. `copilot_1` присваивает обоим 90 и выбирает
`a` по коду; самостоятельный Token Sort даёт 50 и 90 и выбирает `b`.
Это доказывает различие поведения, но не доказывает качество на товарах.

## Что сохранено и адаптировано

- Формулы всех шести методов и нормализация донора сохранены. Нормализация
  вынесена в `cpu6_normalization.py`, чтобы не менять прежние алгоритмы.
- В проверке 784 пар на метод исходные и перенесённые scores совпали:
  всего 4 704 парных проверки, включая реальные названия каталога и края.
- Внутреннее значение 0..1 доступно в `raw_score`. Для существующего
  интерфейса формируется `similarity_pct` 0..100 с двумя знаками.
- Вместо единственного Top-1 методы возвращают общий список кандидатов
  для всех строк чека. Общий слой затем применяет остатки, цену и Top-N.
- При равных отображаемых оценках порядок определяет цена, затем строковый
  код — по правилам нашего проекта. Это отличается от выбора донора только
  по исходному score и коду, если округление создало равенство.
- Нулевой score не создаёт кандидата. Exact и Jaccard могут вернуть пустой
  список. Ведущие нули кодов сохраняются.
- Остатки обрабатывает наш общий слой: дефицитные позиции могут попасть
  в таблицу №2. Предварительная фильтрация всех неположительных остатков
  из экспериментального загрузчика не переносилась.
- Подготовленные названия кэшируются для двух последних снимков в каждом
  CPU-процессе и используются повторно разными методами.

Голосование, автоматическое назначение, feedback-хранилище и CLI донора
не подключались. Новые методы участвуют в существующем параллельном запуске;
база данных и дополнительные зависимости не нужны.

Функциональная проверка и совпадение формул не являются оценкой точности
аналогов. Для неё нужны проверенные пользователем товарные пары.
