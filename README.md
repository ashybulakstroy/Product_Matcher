# Matching Product MVP

Проект предназначен для подбора аналогов товара по двум входным источникам:

1. Торгсофт чек — список позиций из чека / фискального документа.
2. Остатки товаров 1С — актуальные остатки по справочнику / выгрузке 1С.

Для работы проект использует данные из родительского проекта [Prj_16_OCR](C:/Work/Projects/Prj_16_OCR), с сохранением той же структуры каталогов и подхода к хранению данных.

## Основная задача MVP

Для каждой позиции чека нужно вернуть Top-N кандидатов из остатков 1С, отсортированных по убыванию процента сходства.

## Многократные алгоритмы поиска аналогов

Система должна поддерживать несколько независимых алгоритмов поиска аналогов. Каждый алгоритм должен иметь свой уникальный идентификатор и общую схему представления результатов.

Требования:

1. Каждый алгоритм должен иметь свой идентификатор, например `copilot_1`.
2. Результаты поиска по каждому алгоритму выводятся отдельно на странице тестирования.
3. На основной странице отображается только лучший кандидат, найденный этим алгоритмом.
4. В таблице №1 должна быть колонка с идентификатором алгоритма и ссылкой на полный список кандидатов по этому алгоритму.
5. В таблице №2 показывается первый кандидат с недостаточным количеством товаров для этого алгоритма.
6. В таблице №2 также должно показываться имя алгоритма, который предложил этого кандидата, с ссылкой на полный список кандидатов по этому алгоритму.
7. Добавление нового алгоритма выполняется через основную страницу конфигурации алгоритмов.
8. Текущий рабочий алгоритм называется `copilot_1`.

Формат данных для API должен включать:

```json
{
  "algorithm_id": "copilot_1",
  "best_candidate": {"stock_id": "s1", "stock_name": "Молоко ...", "similarity_pct": 96.7},
  "results_by_algorithm": [
    {
      "algorithm_id": "copilot_1",
      "algorithm_name": "copilot_1",
      "items": [
        {
          "candidates": [],
          "excluded_candidates": []
        }
      ],
      "best_candidate": {},
      "low_stock_candidate": {}
    }
  ]
}
```

В текущем коде используется алгоритм `copilot_1` как основной и обязательный идентификатор для тестирования и веб-проверки.

## Запуск

Веб-интерфейс и подбор аналогов работают на одном сервере. Главная страница
использует локально перенесённые OCR, API заданий, счета/PDF и обмен с 1С
из проекта №16; `/analog` сохраняет алгоритмы проекта №17.
Код и OCR-модель находятся в №17, работающий сервер №16 не требуется.
Адрес и порт задаются `OCR_WEB_HOST` и `OCR_WEB_PORT` в `.env`.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m App.web_server
```

Прежний запуск `python -m App.web_debug` также запускает объединённый сервер.
Команда `python -m App` ниже остаётся консольным примером подбора.

```powershell
.\.venv\Scripts\python.exe -m App
.\.venv\Scripts\python.exe -m pytest App/tests -q
```

## SQL STR 3

На `/analog` доступен `sql_str_3` рядом с `sql_str_2` и `copilot_1`.
Версия 3 учитывает редкость слов в текущем каталоге, сравнивает слова целиком
с ограниченным допуском опечаток, отдельно проверяет модели и числовые признаки.
Масса, объём и длина приводятся к общим единицам (`2,5 кг` = `2500 г`).
Отличающиеся характеристики снижают оценку; отсутствующие получают меньший штраф.
В полном списке показаны причины оценки. Процент является рейтингом, а не
вероятностью правильного соответствия. Синонимы, сложные размерные цепочки
и смысловая взаимозаменяемость пока требуют отдельной доработки.
Качество на проверенной пользователем выборке ещё не измерено.


В формах главной страницы и `/analog` можно задать цену за единицу.
Для всех трёх алгоритмов при одинаковом `similarity_pct` кандидаты сортируются
по абсолютному отклонению цены, до ограничения Top-N и с учётом остатков.
Источник цены каталога — `accounting_price` (учётная цена 1С), не цена продажи.
Цены должны относиться к одинаковой валюте, единице и налоговой основе;
автоматического пересчёта НДС, валюты или фасовки этот критерий не выполняет.
Пустая цена запроса сохраняет прежний порядок. Кандидаты без цены при равных
процентах идут после кандидатов с известной ценой. Нулевая цена допустима.
Цена используется только для ранжирования; цены чека и счёта не изменяются.


## OpenCode 4

`opencode_4` доступен на главной и `/analog`, включён в сравнение всех алгоритмов.
Реализация: `App/services/opencode_matching.py`. Основа — идеи исследований
`C:/Temp/OpenCodeTest/opencode/analyze_failure_causes.py`, `analyze_brand_color.py`
и примеры `failure_causes.txt`; готового алгоритма в источнике не было.
Новая реализация использует взвешенное сравнение слов и отдельные проверки
вида товара, полного артикула, модели/серии, размерных цепочек, цвета и марки.
Размеры с указанными единицами приводятся к общей шкале. Причины оценки
передаются в `match_reasons`. Цена разрешает равные баллы через общий слой API.
Словари видов, марок и цветов ограничены; нераспознанная характеристика
не является доказательством совпадения. Однобуквенные цвета не угадываются.
Справочник с предварительными предложениями не используется как обучение
или подтверждённая разметка. Превосходство на проверенной выборке не измерено.
