# Техническое задание ИИ-программисту (Codex/OpenCode) — COMPLETE, SELF-CONTAINED V3

## А. ЖЁСТКОЕ УСЛОВИЕ

Этот ZIP — **полная новая независимая поставка**. Не пытайся искать и не требуй
`Trial_Geometry_Benchmark_V1`, `Trial_Geometry_Benchmark_V2`, `trial_geometry/`,
`run_stageB_smoke`, `run_stageC_smoke`, старые JSON или отчёты. Не читай их как входные данные,
не импортируй оттуда код и не копируй оттуда метрики. Если в репозитории обнаружен старый
Trial, оставь его нетронутым и игнорируй. Используй все исходники из ЭТОГО ZIP.

Только один внешний источник данных: <PROJECT_ROOT>/web_outputs/<job_id>/, исключительно для чтения.
Зависимости: только публичные Python-пакеты NumPy и OpenCV; SciPy опциональна.
Никаких PyTorch, нейросетевых весов, скачивания репозиториев или лицензий с ограничением на бизнес-использование.

## Б. РЕЗУЛЬТАТ, КОТОРЫЙ НУЖНО ПОЛУЧИТЬ

На одном и том же наборе **реальных, уникальных** фото товарных чеков Торгсофт:
- определить реальную печатную сетку до деформации (5 границ четырёх колонок, горизонтальные строки);
- построить исходное -> прямоугольное выпрямление и обратные карты координат;
- получить синюю сетку из ТОЙ ЖЕ геометрии, не из независимых процентов;
- визуально и численно сравнить методы на реальных фото и доказать границы с помощью GT;
- не объявлять успех, если нет наблюдаемых линий или GT.

Не применять частные коррекции под конкретные номера чеков или ожидаемые цены/НДС.

## В. СОСТАВ — УЖЕ НАПИСАН, ИСПОЛЬЗУЙ

- `geometry_lab/cases.py` читает только `web_outputs`, исключает дубликаты, получает baseline
  из текущих файлов основного проекта, а не из прошлого Trial.
- `geometry_lab/detection.py` находит физические линии. Нужно проверить на реальных фото:
  особенно слабые, пунктирные, волнистые и перебитые складками.
- `geometry_lab/algorithms.py` предоставляет готовые вызываемые функции:
  `perspective`, `mesh`, `tps`. Включены все реализации, ничего скачивать отдельно не требуется.
- `geometry_lab/metrics.py` проверяет якобиан и GT, возвращает статусы,
  пересчитывает координаты печатных линий обратно на оригинал.
- `run.py` предоставляет запуск из CLI и отчёт.
- `annotate.html` позволяет создать независимую разметку GT на оригинале в браузере.

## Г. ПОРЯДОК ВЫПОЛНЕНИЯ

1. Распакуй пакет целиком в <PROJECT_ROOT>/Standalone_Torgsoft_Geometry_Lab_V3.
2. Проверь `git status`, чтобы сохранить все рабочие изменения. Изменять только файлы
   внутри `Standalone_Torgsoft_Geometry_Lab_V3/`; результат писать только в
   `<PROJECT_ROOT>/data/output/geometry_benchmark/`.
3. Установи зависимости В ОТДЕЛЬНОЕ venv (руководство `README.md`).
4. Запусти unit-тесты. Проверь, что нет импортов App и предыдущего Trial.
5. Выполни `discover`: выведи число уникальных фотографий, SHA256 и список разных
   случаев. Не считай повторную обработку одной фотографии новым чеком.
6. Запусти `benchmark` для всех методов на 10 уникальных реальных фото. При недоступности
   SciPy `tps_scipy` выдаёт `REJECTED`, но не подменяй его `baseline`.
7. Открой HTML и картинки: сравни геометрию и красные/синие/зелёные линии.
8. Сделай GT вручную через `annotate.html` для хотя бы 5 **разных реальных** чеков:
   прямой, волнистый, нижний угол, помятый, надломленный. Если типов нет — прямо напиши
   `НЕ НАЙДЕНО`, не подменяй синтетикой. Не ставь GT по синей сетке.
9. Повтори benchmark с эталонами. Раздельно отчитай об обнаружении, точности и
   полноте строк/столбцов. Полностью откажись от числовой «точности», если GT_MISSING.
10. Проверь по каждому методу физическое положение строк и столбцов, ошибки фолдинга,
    долю выхода за края, сохранность написанных наименований и чисел. Чтение OCR не
    требуется для этого геометрического Trial.
11. Если детектор не находит достаточно линий — НЕ добавляй придуманную сетку и не
    возвращай `SUCCESS`; исправляй только универсальную геометрию/детектор, затем
    перезапускай полный набор тестов.
12. Сохрани итоговые `summary.html`, `run.json`, по-чековые JSON, изображения.
    Составь `FINAL_FINDINGS.md`: реальные запуски, характеристики Windows CPU,
    скорость, успех/отказ, точность GT, лицензии, препятствия, рекомендации.

## Д. КРИТЕРИИ ПРИЁМКИ

- Работа не зависит от наличия V1/V2, старых trial-папок или отчетов.
- В ZIP содержатся все исходники методов, CLI, тесты, документы, пример синтетики.
- Результат возможен при наличии только Python и `web_outputs`; без SciPy работает 2 метода
  и baseline при наличии; с SciPy добавляется TPS.
- Отсутствующая фотография/карта/GT не приводит к ложной успешности.
- Оригиналы в `web_outputs` никогда не изменяются (сравнить SHA256 и mtime до/после).
- Ни одна строка `App/` не изменена; проверка `git diff -- App`.
- HTML открывается локально `file:///`, картинки доступны с относительными путями.
- Синтетические тесты отдельно от реальных: **никаких заявлений о пригодности только на синтетике**.
- Для метода, претендующего на готовность, нужны координатные ошибки GT,
  число пропусков линий, проверка текста/строк, отсутствие новых дефектов и сравнение с baseline.

## Е. УЧЕСТЬ ТЕКУЩИЕ ПРОБЛЕМЫ, НЕ ЗАВИСЯ ОТ ИХ РЕЗУЛЬТАТОВ

- Отсутствие зелёной горизонтальной линии может означать отказ детектора, а не
  отсутствие реальной физической линии. Не приравнивай обнаружение=0 к совпадению=0.
- Боковая крайняя вертикаль может быть слабой/перекрытой; проверяй количество отдельно.
- Если бумага имеет разрыв, перекрытие или сложную складку, однозначное восстановление
  из одной фотографии иногда невозможно. Нужна честная неопределённость.
- Сумма чека, НДС и OCR не должны использоваться для подгонки геометрии.
