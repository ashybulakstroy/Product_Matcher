# Инструкция по чтению справочника соответствий Торгсофт → 1С

**Версия инструкции:** 30.10.2026  
**Описываемый файл:** `Справочник Торгсофт-1С описание модель марка вид 24722.csv`  
**Назначение:** читать результаты подбора номенклатуры 1С к товарам Торгсофт и отличать *кандидата* от *подтверждённого соответствия*.

> **Главное правило:** файл содержит **предложения для сопоставления**, а не 24 722 подтверждённых соответствия. Даже строку с высоким процентом запрещено автоматически считать проверенной. Поле `Оператор подтвердил` в исходном файле равно `Нет` для всех строк.

## 1. Что находится в файле

- **24 722 строки товаров Торгсофт**, из выгрузок «Данные первый этаж» и «Данные Рынок».
- Для каждой строки указан **основной (лучший по расчётной оценке) кандидат 1С** и до **четырёх альтернатив** — всего до пяти кандидатов.
- Есть оценка сходства в процентах, статус, основание подбора и возможные конфликты характеристик.
- Таблица отсортирована по **`Оценка, %` по убыванию**.
- **Низкие проценты не отсекаются**. Если аналога не удалось установить, показан просто ближайший найденный товар 1С, который может быть совершенно другим изделием.
- Источником 1С служила предоставленная выгрузка «Склад Алатау на 16.10.2026.xls». Это материальная ведомость; отсутствующий в ней товар **не обязательно отсутствует в полном справочнике 1С**.

## 3. Статусы, фактическое количество строк и порядок действий

## 4. Как читать одну строку: два реальных примера

### Пример A — убедительный кандидат

- **Торгсофт:** `ЛОПАТА ШТЫКОВАЯ УНИВЕРСАЛЬНАЯ 0011500 БЕЗ ЧЕРЕНКА "TULEX" @`.
- **1С:** `Лопата TULEX 0011500 штыковая универсальная без черенка`.
- **Код 1С:** `00000016122`.
- **Оценка:** `99.8`.
- **Статус:** `Высокая уверенность — проверить перед применением`.

Назначение, марка, модельное обозначение и комплектность выглядят согласованными. Тем не менее поле `Модель совпадает` в этой строке равно `Нет`: отдельный автоматический индикатор может не распознать модель даже при наличии её в названии. **Сравнивать необходимо сами названия и характеристики, а не отдельный флажок.**

### Пример B — высокий процент, но потенциально неверный матчинг

- **Торгсофт:** колесо для тачки `3.25/3.00-8 ... PU, 20MM`.
- **Кандидат 1С:** колесо `3.25/3.00-8 ... 16MM`.
- **Оценка в CSV:** `99.8`.
- **Поле конфликтов:** пустое.

Здесь фигурируют **20 мм и 16 мм** — существенное различие, которое требует проверки. Это **не готовое подтверждённое совпадение**, несмотря на 99.8% и пустое поле конфликтов. Пример показывает ограничение алгоритмических оценок, а не правило, по которому можно автоматически утверждать высокий процент.

## 5. Как открыть CSV в Excel без повреждения идентификаторов

Используйте импорт, а не двойной щелчок по файлу:

1. Откройте Excel и пустую книгу.
2. Выберите **Данные → Из текста/CSV**.
3. Выберите `Справочник Торгсофт-1С описание модель марка вид 24722.csv`.
4. Укажите кодировку **UTF-8**, разделитель **точка с запятой (;)**.
5. Нажмите **Преобразовать данные** (Power Query) и установите тип **Текст** как минимум для колонок `Артикул Торгсофт`, `Код кандидата 1С`, `Кандидат №2 код 1С` … `Кандидат №5 код 1С`.
6. Для `Оценка, %` и остальных оценок укажите числовой тип с учётом десятичной точки/локали либо импортируйте их текстом и преобразуйте отдельно.
7. Нажмите **Закрыть и загрузить**. После этого можно фильтровать и сортировать по статусу, точке, артикулу и оценке.

**Проверка импорта:** код `00000016122` должен остаться именно `00000016122`, а не `16122`.


Правила для интеграции и последующей обработки:

1. **Читать все 24 722 строки**, не отбрасывая низкие оценки.
2. **Не приводить** коды 1С и артикулы Торгсофт к числам; сохранять ведущие нули.
3. **Не считать** `Код кандидата 1С` доказанным соответствием. В текущем файле он есть даже при статусе `Аналог не установлен`.
4. **Не разрешать автоматическую замену товара** на основе одного только процента, совпадения марки или товарной группы.
5. **Проверять критические атрибуты**: модель/модификацию, длину, диаметр, толщину, мощность, цвет, количество в упаковке, единицы учёта, комплектность, назначение.
6. **Считать пустые поля конфликтов и флажков неопределённостью**, а не гарантией совпадения.
7. **Обрабатывать альтернативы №2–5** как независимых неподтверждённых кандидатов.
8. **Сохранять связь с исходной точкой Торгсофт и исходной строкой**. Не предполагать, что одно название либо один артикул встречается только однажды во всех выгрузках.
9. **Не использовать остаток Торгсофт вместо остатка 1С** и не выбирать код 1С только по наличию остатка.
10. Для рабочего словаря подтверждённых соответствий хранить отдельно как минимум: идентификатор позиции Торгсофт, **подтверждённый** идентификатор/код 1С, дату, источник подтверждения, версию выгрузок и статус проверки.

> **Ограничение достоверности:** текущая таблица получена автоматизированным подбором и дополнительной проверкой некоторых характеристик. Это не результат гарантированной индивидуальной экспертной проверки каждой пары языковой моделью. `Оценка, %` не является откалиброванной вероятностью идентичности товара.

## 7. Как использовать CSV в проекте Торгсофт ↔ 1С

Справочник можно использовать как **входную таблицу кандидатов для трансформации**, но **не как окончательный реестр проверенных соответствий**:

1. Найти товар чека в исходных записях Торгсофт.
2. Получить основного кандидата 1С и четыре альтернативы.
3. Проверить критические характеристики, единицы измерения, наличие фактического аналога и статус ручного подтверждения.
4. Если достоверное соответствие не установлено — показать варианты оператору в интерфейсе, не подставлять случайный код.
5. После подтверждения сохранить соответствие в **отдельном постоянном справочнике проверенного маппинга**. При дальнейших счетах использовать именно подтверждённый маппинг.

**Итоговое правило:** ближайший кандидат 1С ≠ установленный аналог ≠ подтверждённое соответствие. Эти три состояния должны различаться в приложении и данных.
