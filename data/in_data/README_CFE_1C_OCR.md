# Установка и использование расширения 1С (`.cfe`)

**Проект:** интеграция чеков Торгсофт → OCR → 1С:Бухгалтерия для Казахстана 3.0  
**Документ:** `СчетНаОплатуПокупателю` («Счёт на оплату покупателю»)  
**Назначение:** инструкция по установке и проверке расширения, которое будет создано для интеграции с OCR.

> Внимание: файл `.cfe` пока не предоставлен. Эта инструкция описывает процедуру подключения, но **не подтверждает**, что в расширении реализованы определённые команды, HTTP-вызовы или правила заполнения. Перед выпуском нужно дополнить раздел «Паспорт расширения» фактическими данными.

## 1. Паспорт расширения — заполнить при сборке

| Поле | Значение |
|---|---|
| Имя файла | `<имя_расширения>.cfe` |
| Имя расширения в 1С | `<указать>` |
| Версия расширения | `<указать>` |
| Дата сборки | `<указать>` |
| Поддерживаемая конфигурация | `Бухгалтерия для Казахстана`, редакция 3.0; проверить на установленной версии |
| Версия платформы 1С | `<минимальная протестированная>` |
| Ответственный разработчик | `<указать>` |
| Проверенный сценарий | `<описать после испытаний>` |

Референсный анализ исходных XML-метаданных проводился на конфигурации **3.0.71.1**. Это не означает автоматическую совместимость с любой версией рабочей базы.

## 2. Перед установкой

1. Уточнить название и версию рабочей информационной базы 1С, проверить права администратора.
2. Сохранить резервную копию **информационной базы** штатным способом (средства администрирования сервера/СУБД или конфигуратор — в зависимости от типа базы). Проверить возможность восстановления.
3. По возможности сначала установить `.cfe` в **тестовую копию** базы, а не в рабочую.
4. Для работ, требующих эксклюзивного доступа, согласовать выход остальных пользователей и остановку фоновых заданий.
5. Сохранить исходный `.cfe` и номер версии для возможного отката.

## 3. Установка через 1С:Предприятие (если раздел доступен)

1. Войти в тестовую базу с правами администратора.
2. Перейти **Администрирование → Печатные формы, отчёты и обработки → Расширения** (названия разделов могут различаться в конкретной редакции).
3. Нажать **Добавить из файла** или **Добавить** и выбрать `<имя_расширения>.cfe`.
4. Прочитать предупреждение безопасности и проверить, что выбран именно доверенный файл.
5. Убедиться, что расширение появилось в списке и включено в использование.
6. Если расширение требует доступа к HTTP или другим внешним ресурсам, проверить ограничения безопасного режима. **Не отключать безопасный режим автоматически:** только после проверки кода и оценки рисков; если необходимое действие блокируется — согласовать исключение с администратором.
7. Перезапустить сеанс 1С; при необходимости перезапустить клиентские сеансы пользователей.

Альтернативный путь указан далее, если список расширений отсутствует либо установка требует Конфигуратора.

## 4. Установка через Конфигуратор

1. Войти в **Конфигуратор** нужной информационной базы.
2. Выбрать **Конфигурация → Расширения конфигурации**.
3. Добавить новую строку расширения. **Не загружать новый файл поверх чужого действующего расширения**.
4. Выделить именно созданную строку; в меню окна расширений выбрать **Конфигурация → Загрузить конфигурацию из файла…** и указать `.cfe`.
5. Сохранить и применить изменения расширения в базе согласно подсказкам текущей версии платформы; если платформа предлагает **Обновить конфигурацию базы данных (F7)** — выполнить после проверки предупреждений и с резервной копией.
6. Перезапустить сеанс 1С:Предприятия и убедиться, что расширение активно.

**Не загружать `.cfe` командой «Загрузить конфигурацию из файла» для основной конфигурации** — это другая операция.

## 5. Проверка после установки

### 5.1. Проверка доступности

1. Открыть **Продажи → Счета на оплату покупателю** (путь в меню может отличаться).
2. Создать **новый, пока не записанный** документ для теста.
3. Проверить наличие команд расширения, если они реализованы в данном `.cfe` (ожидаемые имена по техническому замыслу: **Запустить OCR**, **Забрать результат**).
4. Убедиться, что штатные команды документа, выбор контрагента и работа табличной части **Товары** не нарушены.

### 5.2. Интеграционный сценарий — только если реализован в расширении

1. Подготовить тестовую фотографию чека Торгсофт, используя обезличенные данные.
2. Запустить OCR через предусмотренную команду; проверить, что создана задача и получен идентификатор задачи `task_id`.
3. Дождаться готовности результата штатным способом; получить результат без повторного создания задачи.
4. Проверить соответствия номенклатуры 1С, количество, цену, сумму строки, НДС и итоги.
5. Неопределённые соответствия должны быть явно отмечены; нельзя незаметно подставлять произвольный товар.
6. Проверить остатки **на стороне 1С** по актуальным данным рабочей базы, если это реализовано.
7. Проверить реакцию на ошибки сети, пустой ответ, повторное получение результата и повторное нажатие команды.
8. Проверить, что работа с новым документом не зависит от его записи только ради получения идентификатора OCR-задачи. Внешний `task_id` не должен путаться со ссылкой документа 1С.

**Тестовый счёт не записывать в производственную базу без отдельного разрешения.** Документ `СчетНаОплатуПокупателю` в анализируемой версии не проводится; это не отменяет необходимости контролировать его реквизиты и итоговые суммы.

## 6. Частые проблемы

| Симптом | Что проверить |
|---|---|
| Расширение не видно | Правильная ли база, установка завершена ли, активность расширения, перезапуск клиента |
| Кнопки не появились | Реализованы ли они в `.cfe`, привязаны ли к форме документа, есть ли права пользователя |
| Ошибка применения расширения | Версия платформы, конфигурации, несовпадение заимствованных объектов после обновления |
| Ошибка HTTP / подключения | Адрес OCR-сервера, доступность из среды выполнения 1С, TLS, сетевые правила, ограничения безопасного режима |
| Не найден товар | UUID и существование номенклатуры в **этой** базе, правила маппинга и список кандидатов |
| Неверные остатки | Организация, дата, склад, настройки бухгалтерского/складского учёта и источник остатков |
| Не совпали суммы | Количество, цена, режим включения НДС, ставка НДС и правила округления |

## 7. Откат или отключение

1. Сначала остановить тестирование и сохранить текст ошибки/журнал регистрации.
2. Открыть список **Расширения** и **отключить** проблемное расширение, если интерфейс и тип расширения это позволяют.
3. Перезапустить 1С и убедиться, что штатный документ открывается.
4. Если требуется полное удаление — удалить **только наше расширение** после резервного копирования и проверки, что оно не содержит данных, потеря которых недопустима.
5. При повреждении данных или конфигурации восстановить проверенную резервную копию в установленном порядке.

## 8. Обновление `.cfe`

1. Зафиксировать текущую версию, сделать резервную копию.
2. Установить новую версию **в тестовой базе** поверх соответствующего существующего расширения (не создавать случайный дубль).
3. Повторить проверки раздела 5, особенно создание нового счёта и интеграционный сценарий.
4. Только после успешных проверок обновлять рабочую базу.

## 9. Что разработчик должен добавить к релизу

- Готовый `<имя_расширения>.cfe`.
- Заполненный паспорт версии и проверенную матрицу совместимости.
- Перечень добавленных команд и их расположение в интерфейсе.
- Настройки адреса OCR-сервиса, таймаутов и авторизации **без публикации секретов**.
- Описание формата обмена и обработки ошибок.
- Результаты испытаний на тестовой базе, а при изменениях OCR — также на реальных фотографиях чеков.
- Инструкцию по откату и историю изменений.

## 10. Важные ограничения

- `.cfe` — файл расширения конфигурации 1С, а не самостоятельная программа и не Python-модуль.
- Установка производится **в выбранную информационную базу**; другие базы не изменяются автоматически.
- Перед каждым обновлением конфигурации нужно проверять совместимость расширения.
- Конкретная реализация кнопок и HTTP-обмена должна быть подтверждена содержимым готового `.cfe`, а не предположена из названия файла.
